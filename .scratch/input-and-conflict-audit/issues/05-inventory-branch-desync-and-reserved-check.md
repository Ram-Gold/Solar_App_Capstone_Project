# Manual product edits and RecordSaleModal desync branch stock sums and can fail reserved_quantity <= stock_quantity constraint

## Problem & Verification
Verified in `RecordSaleModal.jsx`, `inventoryUtils.js` (`executeManualSale`), `DashboardScreen.jsx`, `ProductsScreen.jsx`, `AddProductScreen.jsx`, and live Postgres constraint `chk_products_reserved_quantity` (`CHECK (reserved_quantity >= 0 AND reserved_quantity <= stock_quantity)`):

1. `RecordSaleModal` has no branch selector and calls `executeManualSale(supabase, product, qty)` defaulting to `'Quiapo'`, while validating against global `getAvailableQuantity(product)`. If Quiapo has `0` units and Cavite has `5`, selling `2` clamps `stock_quiapo` to `0` while reducing `stock_quantity` from `5` to `3` (`stock_quiapo + stock_cavite !== stock_quantity`).
2. `DashboardScreen` (`handleQuickRestockSave` and `handleEditSave`) updates `stock_quantity` directly without updating `stock_quiapo` / `stock_cavite`, leaving branch counts stale.
3. Neither `DashboardScreen` nor `ProductsScreen` validates that the new `stock_quantity` (or branch stock) is `>= reserved_quantity`, causing Postgres `chk_products_reserved_quantity` check constraint errors when reducing stock below active holds.
4. `AddProductScreen` assigns all initial stock to `stock_quiapo` with `stock_cavite: 0` and provides no Cavite stock input.

## Recommended Triage
- **Category:** `bug`
- **Recommended State:** `ready-for-agent` (add branch selection & branch-scoped validation to `RecordSaleModal`, enforce `stock >= reserved` across `DashboardScreen` and `ProductsScreen` keeping `stock_quantity = stock_quiapo + stock_cavite`, and support Quiapo/Cavite split in `AddProductScreen`).

## Agent Brief

**Category:** bug
**Summary:** Synchronize Quiapo/Cavite branch stock and enforce reserved-quantity lower bounds across all product stock mutations

**Current behavior:**
1. `RecordSaleModal` defaults all sales to `'Quiapo'` while checking global `getAvailableQuantity(product)` instead of branch-level `getBranchStock(product, branch).available`.
2. `DashboardScreen` updates `stock_quantity` without syncing `stock_quiapo` / `stock_cavite`.
3. Product restock and edit forms allow submitting a total `stock_quantity` below `reserved_quantity` (or branch stock below branch reserved stock), causing Postgres `chk_products_reserved_quantity` constraint violations or inventory drift.
4. `AddProductScreen` forces all initial inventory into `stock_quiapo` (`stock_cavite: 0`).

**Desired behavior:**
1. `RecordSaleModal` includes a Quiapo/Cavite branch selector, validates `unitsSold <= getBranchStock(product, branch).available`, and passes the selected branch to `executeManualSale()`.
2. `executeManualSale()` checks branch available units via `getBranchStock(product, branch)` (not only global available stock) and recomputes `stock_quantity = newQuiapo + newCavite`.
3. All restock and product edit handlers across `DashboardScreen` and `ProductsScreen` keep `stock_quantity`, `stock_quiapo`, and `stock_cavite` synchronized and block saving if `newStock < reserved_quantity` or `newBranchStock < reserved_branch`, showing an actionable error message explaining active holds.
4. `AddProductScreen` accepts explicit Quiapo and Cavite initial stock counts and sets `stock_quantity = stock_quiapo + stock_cavite`.

**Key interfaces:**
- `executeManualSale(supabaseClient, product, unitsSold, branch)` and `getBranchStock(product, branch)` in inventory utilities
- `RecordSaleModal` props and branch selection state
- `ProductsScreen`, `DashboardScreen`, and `AddProductScreen` stock validation/persistence handlers

**Acceptance criteria:**
- [ ] Attempting to record a Quiapo sale in `RecordSaleModal` when Quiapo has `0` units and Cavite has `5` is blocked with a branch stock error

- [ ] Restocking or editing a product below active `reserved_quantity` (or branch reserved count) fails client validation cleanly before hitting `chk_products_reserved_quantity`
- [ ] Creating a product in `AddProductScreen` allows splitting initial stock between Quiapo and Cavite with `stock_quantity` equal to their sum
