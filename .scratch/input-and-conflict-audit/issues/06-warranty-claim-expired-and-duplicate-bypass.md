# Customers can submit claims on expired warranties or file duplicate claims on the same unit

## Problem & Verification
Verified in `EquipmentCard.jsx`, `FaultDiagnosticModal.jsx`, `customerService.js` (`submitWarrantyClaim`), and live Postgres `submit_warranty_claim(p_token, p_purchase_id, p_category, p_description, p_media_urls)`:

1. `EquipmentCard` disables claim filing (`isSupportOnly`) only for voided purchases or purchases with a prior approved/resolved replacement—so units whose warranty has **expired** (`!purchase.is_warranty_active`) still display an enabled **File Claim** button.
2. Live Postgres `submit_warranty_claim` checks only `access_token` ownership; it does **not** enforce `NOT is_voided`, `warranty_expires_at >= CURRENT_DATE`, absence of prior fulfilled 1-time replacement, or absence of an existing open (`pending` / `in_review`) claim on that `purchase_id`.
3. Additionally, `customerService.js` falls back to a raw client `INSERT` into `warranty_claims` whenever the RPC returns `success: false` or an error, bypassing RPC checks whenever `anon` insert RLS permits it.

## Recommended Triage
- **Category:** `bug`
- **Recommended State:** `ready-for-agent` (gate **File Claim** in `EquipmentCard` and `FaultDiagnosticModal` when expired or when an open claim already exists, update `submit_warranty_claim` in live Supabase to enforce warranty validity + duplicate prevention, and stop falling back to direct `INSERT` when the RPC intentionally rejects a claim).

## Agent Brief

**Category:** bug
**Summary:** Block expired, voided, already-replaced, and duplicate open warranty claims in both UI and live Supabase RPC

**Current behavior:**
`EquipmentCard` enables the **File Claim** action for expired purchases (`!purchase.is_warranty_active`) and purchases with an already-open pending/in-review claim. On the backend, Postgres `submit_warranty_claim` verifies only customer token ownership, and `submitWarrantyClaim()` falls back to a direct client `INSERT` into `warranty_claims` even when the RPC returns a business-rule rejection.

**Desired behavior:**
1. `EquipmentCard` and `FaultDiagnosticModal` treat expired purchases (`!purchase.is_warranty_active`), voided purchases, 1-time-replacement-fulfilled purchases, and purchases with an active open claim (`pending`, `in_review`) as ineligible for filing a new warranty claim, routing users instead to **Run Troubleshooting Guide** or **Track Status**.
2. Live Supabase RPC `submit_warranty_claim(p_token, p_purchase_id, p_category, p_description, p_media_urls)` validates inside the database transaction:
   - Purchase is not voided (`COALESCE(is_voided, FALSE) = FALSE`)
   - Warranty has not expired (`COALESCE(warranty_expires_at, ...) >= CURRENT_DATE`)
   - No prior `approved` or `resolved` replacement claim exists for `p_purchase_id`
   - No open `pending` or `in_review` claim currently exists for `p_purchase_id`
3. `submitWarrantyClaim()` surfaces explicit RPC rejection errors (`rpcResult.success === false`) directly to the UI instead of falling back to an unrestricted client `INSERT`.

**Key interfaces:**
- `submitWarrantyClaim({ token, purchaseId, issueCategory, description, mediaUrls })` in the customer service module
- Live Postgres RPC `public.submit_warranty_claim(uuid, uuid, text, text, text[])` applied via `supabase_mcp` `apply_migration`
- `EquipmentCard` coverage state and `FaultDiagnosticModal` claim-form submission guard

**Acceptance criteria:**
- [ ] Expired equipment cards do not render an active **File Claim** button
- [ ] Equipment cards with an open `pending` or `in_review` claim direct the customer to track the existing ticket instead of creating a second claim
- [ ] Calling `submit_warranty_claim` on an expired, voided, replaced, or already-open-claim purchase returns `{ success: false, error: ... }` without inserting a row
- [ ] `submitWarrantyClaim()` throws the RPC rejection reason cleanly without attempting a fallback `INSERT`

**Out of scope:**
- Overhauling table-wide Supabase RLS policies (tracked separately under the RLS security issue)
- Altering non-warranty branch servicing guidance text
