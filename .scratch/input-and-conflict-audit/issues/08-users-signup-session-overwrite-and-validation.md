# Admin user creation uses shared Supabase client signUp and lacks email/password consistency checks

## Problem & Verification
Verified in `UsersScreen.jsx` (`handleSubmit`) compared with `customerService.js` (`createIsolatedAuthClient`):

1. `UsersScreen` creates staff/admin accounts via the primary `supabase.auth.signUp(...)` client rather than `createIsolatedAuthClient()`. Depending on Supabase project auto-confirm settings, `signUp` can swap the active Admin session in the browser to the newly created `staff` user—immediately breaking `<ProtectedRoute>` admin access or causing `admins`/`staff` insert RLS failure.
2. If `supabase.from(tableName).insert(...)` fails after `auth.signUp` succeeds, the created `auth.users` account becomes orphaned with no profile row in `admins` or `staff`, blocking retries with "User already registered".
3. Creation validates `minLength={6}` in HTML only (not `>= 8` like `handleSaveUserPassword`), and `handleSubmit` does not call `isValidEmail(cleanEmail)` before hitting `auth.signUp`.

## Recommended Triage
- **Category:** `bug`
- **Recommended State:** `ready-for-agent` (switch `UsersScreen` user provisioning to an isolated client / secure RPC pattern matching `createIsolatedAuthClient`, enforce `>= 8` char password + `isValidEmail`, and handle partial-creation rollback/recovery cleanly).

## Agent Brief

**Category:** bug
**Summary:** Provision staff and admin accounts without overwriting the active admin browser session and enforce consistent email/password validation

**Current behavior:**
`UsersScreen` invokes `supabase.auth.signUp` on the primary authenticated Supabase client, accepts passwords shorter than 8 characters during account creation (while password reset enforces `>= 8`), skips `isValidEmail()` checks before calling `signUp`, and leaves an orphaned `auth.users` row if inserting into `admins` or `staff` fails.

**Desired behavior:**
1. Account creation uses an isolated non-persisting Supabase client (`createIsolatedAuthClient()`) or a dedicated `SECURITY DEFINER` admin RPC so the signed-in administrator's browser session is never overwritten.
2. `handleSubmit` validates `isValidEmail(cleanEmail)` and enforces a minimum 8-character password (matching password management rules) before calling Supabase.
3. If `auth.signUp` succeeds without returning a user or if inserting into `admins` / `staff` fails, surface a clear error message indicating the partial failure state and do not leave the admin signed out.

**Key interfaces:**
- `UsersScreen` create-user submit handler and form inputs
- `createIsolatedAuthClient()` in the Supabase client module
- `isValidEmail`, `sanitizeEmail`, `sanitizeText`, `sanitizePhone`, `isValidPhone` utilities

**Acceptance criteria:**
- [ ] Creating a staff or admin account preserves the current admin's authenticated session
- [ ] Account creation rejects malformed emails and passwords shorter than 8 characters consistently with password updates
- [ ] Partial insert errors are surfaced cleanly in the Users management error banner without logging the admin out

**Out of scope:**
- Changing `deletePlatformUser` or `adminSetUserPassword` RPC contracts
