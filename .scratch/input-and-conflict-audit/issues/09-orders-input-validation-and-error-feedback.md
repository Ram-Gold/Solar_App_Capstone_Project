# OrdersScreen lacks input sanitization, numeric bounds checks, and surfaced error feedback

## Problem & Verification
Verified in `OrdersScreen.jsx` (`handleSubmit`, `handleDelete`):

1. `handleSubmit` sets `price: Number(form.price)` and `quantity: Number(form.quantity)` without validating `quantity >= 1` integer, `price >= 0`, or checking `Number.isNaN`, allowing negative or fractional quantities/prices.
2. Text inputs (`customer_name`, `address`, `product_name`) are persisted directly without `sanitizeText`.
3. Failed Supabase `insert`, `update`, or `delete` calls silently ignore `error` without displaying any alert/toast, and deletion uses blocking browser `confirm(...)` instead of the app's confirmation modal pattern.

## Recommended Triage
- **Category:** `bug`
- **Recommended State:** `ready-for-agent` (add `sanitizeText` + `sanitizeNumber` validation, display inline error feedback on Supabase errors, and replace native `confirm()` with an in-app confirmation modal).

## Agent Brief

**Category:** bug
**Summary:** Sanitize text inputs, validate numeric bounds, and surface Supabase errors in Order Management

**Current behavior:**
`OrdersScreen` submits raw text fields directly to Supabase, converts `quantity` and `price` via unchecked `Number(...)`, ignores Supabase `error` objects on create/update/delete, and relies on browser `window.confirm()` for deletion.

**Desired behavior:**
1. Text inputs (`customer_name`, `address`, `product_name`) are sanitized with `sanitizeText` and checked for non-empty values before submission.
2. `quantity` is validated as a positive integer (`>= 1`) and `price` as a finite number (`>= 0`) via `sanitizeNumber`, with inline validation errors shown on invalid values.
3. Supabase errors on `fetchOrders`, `insert`, `update`, and `delete` display visible error feedback in the UI rather than failing silently.
4. Order deletion uses an accessible in-app confirmation modal matching the rest of the admin workspace rather than native `window.confirm()`.

**Key interfaces:**
- `OrdersScreen` form submission and deletion handlers
- `sanitizeText` and `sanitizeNumber` utilities
- `useModalBehavior` hook for accessible delete confirmation

**Acceptance criteria:**
- [ ] Negative/zero quantities and negative prices are rejected with an inline validation message
- [ ] Customer name, address, and product name are stripped of HTML/script tags before persisting
- [ ] Failed Supabase insert/update/delete requests surface an error banner to the user
- [ ] Order deletion renders an in-app confirmation dialog supporting Escape/backdrop dismissal

**Out of scope:**
- Changing the `orders` database schema or staff/admin column visibility rules
