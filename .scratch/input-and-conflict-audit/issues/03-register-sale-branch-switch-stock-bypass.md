# RegisterSaleScreen skips stock validation when any reservation ticket is linked, allowing overselling across branches or extra line items

## Problem & Verification
Verified in `RegisterSaleScreen.jsx` (`handleSubmit`, `handleSelectReservation`, `branchLocation` selector):

1. In `handleSubmit`, branch stock validation is wrapped in `if (!selectedReservation)`. Once any reservation ticket is selected, stock checks are skipped completely.
2. Staff can link a reservation for Product A at Cavite, then switch `branchLocation` to `Quiapo`, add extra line items (`+ Add Product`), or link an unheld (`is_reservation = false`) `JDS-RES-*` ticket when the selected branch has `0` available units.
3. `registerCustomerAndSale` inserts `customer_purchases` rows and issues a valid warranty QR pass before `fulfill_reservation_sale` clamps `stock_quantity` via `GREATEST(0, ...)`—recording completed sales and warranties for out-of-stock equipment.

## Recommended Triage
- **Category:** `bug`
- **Recommended State:** `ready-for-agent` (validate per-product requested quantity against branch available stock plus only the exact credit held by `selectedReservation` on that same product & branch; block submission on insufficient stock before creating customer purchases).

## Agent Brief

**Category:** bug
**Summary:** Validate per-product branch stock even when a reservation ticket is linked in RegisterSaleScreen

**Current behavior:**
During POS submission, inventory validation checks `getBranchStock(prod, branchLocation).available` only when `selectedReservation` is null. Whenever any reservation is linked, changing the store branch selector, increasing item quantity beyond the reservation, adding extra catalog products, or fulfilling an unheld ticket (`is_reservation = false`) bypasses stock validation and proceeds to create purchase and warranty records even when the branch lacks inventory.

**Desired behavior:**
All POS checkouts must aggregate requested quantities per `productId` against the selected `branchLocation` inventory:
1. For each unique `productId` in `items`, calculate `availableAtBranch = getBranchStock(product, branchLocation).available`.
2. Add a reserved-unit credit equal to `Math.max(1, Number(selectedReservation.quantity) || 1)` **only** when `selectedReservation?.is_reservation === true`, `String(selectedReservation.product_id) === String(productId)`, and `selectedReservation.store_branch` maps to the same branch (`Quiapo` or `Cavite`) as `branchLocation`.
3. If `requestedCount > availableAtBranch + reservationCredit`, block submission with a clear branch-specific error message before inserting any customer or purchase rows.

**Key interfaces:**
- `RegisterSaleScreen` submit handler validation loop over `items`
- `getBranchStock(product, branchLocation)` from inventory utilities
- `selectedReservation` shape (`id`, `product_id`, `quantity`, `store_branch`, `is_reservation`)

**Acceptance criteria:**
- [ ] Switching branch after linking a Cavite Stock Hold fails validation at Quiapo if Quiapo available stock is insufficient
- [ ] Adding extra unreserved products alongside a linked reservation is validated against branch available stock
- [ ] Linked reservations with `is_reservation = false` do not receive reserved-unit credit during stock validation
- [ ] Valid matching-branch Stock Hold checkouts continue to succeed even when `available` unreserved stock is `0`

**Out of scope:**
- Preventing staff from switching branches after selecting a reservation (validation handles safety regardless of order)
- Modifying the live `fulfill_reservation_sale` SQL RPC signature
