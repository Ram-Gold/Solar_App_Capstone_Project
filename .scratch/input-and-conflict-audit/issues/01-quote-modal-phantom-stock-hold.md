# Online Store Pickup submissions set `is_reservation = true` without calling `reserve_product_stock`

## Problem & Verification
Verified in `QuoteModal.jsx` and `InquiriesScreen.jsx`:

1. When a customer submits `QuoteModal` in Store Pickup mode (`mode === 'reserve'`), the form assigns `payload.is_reservation = true` on direct `INSERT` into `quote_tickets` without invoking `reserve_product_stock`, checking branch stock, or capping `quantity` (`quantity + 1` increments without bound even past catalog stock).
2. As a result, `products.reserved_quantity`, `reserved_quiapo`, and `reserved_cavite` remain unchanged while `quote_tickets.is_reservation` is already `true` (a phantom Stock Hold).
3. When staff later opens that `JDS-RES-*` ticket in `InquiriesScreen`, `wasReservation` evaluates to `true`, so clicking **Save Changes** skips `reserve_product_stock`.
4. Worse, if staff unchecks **Hold Stock for Pickup** or sets the ticket to `Completed` / `Cancelled`, `release_product_reservation` still reads `is_reservation = true` and decrements `reserved_quantity` / branch `reserved_*`—potentially stealing reserved units held by a *different* customer's real Stock Hold.

## Agent Brief

**Category:** bug
**Summary:** Keep guest Store Pickup submissions unheld (`is_reservation: false`) until staff approval and cap requested quantity against branch stock

**Current behavior:**
Submitting a Store Pickup inquiry through `QuoteModal` sets `is_reservation = true` directly on insert without reserving units via `reserve_product_stock`, and allows customers to increment `quantity` above branch availability. This produces phantom holds that neither lock inventory nor trigger `reserve_product_stock` when staff later reviews the ticket, while allowing `release_product_reservation` to decrement unrelated reservations if cancelled.

**Desired behavior:**
1. Guest submissions from `QuoteModal` always persist `is_reservation: false` (and `status: 'Pending'`). Stock Holds are activated exclusively after showroom staff confirms stock and enables the hold in `InquiriesScreen` (which invokes `reserve_product_stock`).
2. `QuoteModal` displays real-time branch availability (`getBranchStock(product, selectedBranch).available`) for Store Pickup requests, caps the quantity stepper at `Math.max(1, availableAtBranch)` (or blocks incrementing beyond available branch stock), and informs customers if the chosen branch currently has `0` available units.
3. Update customer confirmation copy in `QuoteModal` so step 3 accurately communicates that the request is pending staff stock-hold confirmation rather than claiming units are already locked.

**Key interfaces:**
- `QuoteModal` payload construction (`is_reservation`, `quantity`, `store_branch`) and quantity stepper controls
- `getBranchStock(product, branch)` utility for branch availability calculation

**Acceptance criteria:**
- [ ] Submitting `QuoteModal` in `'reserve'` mode inserts `is_reservation: false` into `quote_tickets`
- [ ] Switching `selectedBranch` inside `QuoteModal` updates available stock display and clamps `quantity` when exceeding branch availability
- [ ] Staff opening the submitted `JDS-RES-*` ticket can enable **Hold Stock for Pickup** and successfully invoke `reserve_product_stock`
- [ ] Unit/integration tests verify `is_reservation: false` on guest submission and quantity capping against branch stock

**Out of scope:**
- Automatic guest-side calls to `reserve_product_stock` without staff review
- Changing `reserve_product_stock` or `release_product_reservation` RPC signatures
